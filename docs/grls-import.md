# PharmDesk v0.4.1 — загрузка выгрузки ГРЛС без изменения ассортимента

## Что реализовано

Программа разбирает ZIP-выгрузку ГРЛС со вложенными файлами Excel (XLSX)
и создаёт **отдельный локальный каталог исходных реестровых строк**.
Из него можно искать кандидатов для сопоставления с аптечными товарами.
Пока человек не проверил конкретную регистрационную запись,
PharmDesk **не переносит** эти данные в подтверждённый справочник
и не связывает автоматически с товарами.

В этом выпуске **не реализована** автоматическая фоновая синхронизация
или загрузка с веб-сайта ГРЛС по сети.

## Достоверный источник и формат

Минздрав РФ в техническом описании от 01.09.2026 сообщает,
что данные ГРЛС доступны в ZIP на
https://grls.minzdrav.gov.ru/grls.aspx.
Внутри — файлы вида
`grlsГГГГ-ММ-ДД-1-Действующий.xlsx` и аналогичные имена для
других статусов регистрационных удостоверений.

Документ со структурой:
https://minzdrav.gov.ru/special/documents/9892-opisanie-tehnicheskih-trebovaniy-k-vzaimodeystviyu-informatsionnoy-sistemy-posrednicheskoy-tsifrovoy-platformy-s-gosudarstvennoy-informatsionnoy-sistemoy-reestrom

Нужные заголовки из официального описания:
- Номер регистрационного удостоверения;
- Торговое наименование лекарственного препарата;
- Международное непатентованное или химическое наименование;
- Формы выпуска.

Также импортируется владелец регистрационного удостоверения,
если есть соответствующий столбец.

**Не путать:** владелец удостоверения не обязательно является
производителем. Поле «Формы выпуска» часто объединяет несколько форм,
дозировок или упаковок, поэтому программа хранит его исходный текст
**без автоматического разбора и предположений**.

## Использование

1. Остановите сервер PharmDesk (Ctrl+C), обновите приложение через
   `.\update-windows.bat`, затем откройте его через `.\pharmdesk.bat`.
2. В официальном ГРЛС получите актуальную выгрузку ZIP.
3. Откройте локально:
   `http://127.0.0.1:8000/catalog/grls/import`.
4. Выберите ZIP и подтвердите, что скачали его с официального сайта.
5. PharmDesk проверит структуру, имена книг и даты, обязательные
   столбцы, количество строк и ограничение размера.
6. Проверьте **предварительный просмотр** с датой, количеством строк,
   статусами и примерами реестровых записей.
7. Только если всё корректно, введите `ИМПОРТИРОВАТЬ`.
   Приложение запишет записи в отдельные таблицы.
8. В разделе `/catalog/grls` ищите по регистрационному номеру
   или торговому названию; фильтруйте по снимку и статусу.
9. На странице товара нажмите «Искать в выгрузке ГРЛС» и просмотрите
   **возможные совпадения по названию**.
10. Нажмите «Начать ручную сверку». В форму переносятся **только номер
    регистрации и торговое название**. Лекарственная форма,
    дозировка, действующие вещества, производитель и ссылка на
    конкретную запись должны быть заполнены и проверены вручную
    по актуальному официальному источнику.

## Состояния и ограничения

- Система сохраняет SHA-256 скачанного файла, имена вложенных
  книг, дату из имён файлов, статус из имени книги и номер строки.
- Файл остаётся на компьютере, ни один ZIP или реестровая запись
  не отправляется в публичный GitHub.
- **Происхождение файла не удостоверяется цифровой подписью.**
  Программа не может отличить оригинальный файл от поддельного
  файла той же структуры. Подтверждение скачивания делает пользователь.
- Статус из файла имеет смысл **только на дату выгрузки**.
  Файлы старше 30 дней отмечаются как устаревшие. Даже свежий
  файл не гарантирует, что регистрация действует прямо сейчас.
- Программа не предоставляет автоматически инструкции, показания,
  дозировочные рекомендации, взаимодействия или возможность замены.
- Совпадение названия — подсказка для поиска, не удостоверение
  соответствия лекарственной формы и дозировки.
- Данные могут быть неполными: при неизвестной структуре архива
  загрузка прерывается, а не интерпретируется догадками.
- Некоторые версии реестра ЕАЭС предлагают CSV и XML; их формат
  требует самостоятельной проверки. Этот выпуск **не импортирует**
  их автоматически.

## Техническая безопасность

- Размер ZIP — не более 96 МБ, ограничены размеры распакованных XLSX,
  вложенных XML и количество строк.
- Неподдерживаемые книги, разнородные даты снимков, неизвестные
  статусы и отсутствующие обязательные поля отклоняются.
- Перед сохранением контрольная сумма ZIP проверяется повторно.
- Повторная загрузка идентичного ZIP отклоняется по SHA-256.
- Сохранение снимка выполняется в транзакции SQLite;
  никакие старые таблицы товаров, подтверждённых регистрационных
  карточек или ручной сверки не перезаписываются.
- Новые таблицы: `grls_import_batches` и `grls_import_rows`.
- Временный ZIP после предпросмотра находится локально в
  `private_data/grls_previews/` и удаляется после подтверждённого
  импорта. Если загрузку отменить, временный файл пока остаётся
  в локальной папке; при необходимости его можно удалить
  **только после остановки приложения и без затрагивания SQLite**.
- База SQLite и фото копируются существующей безопасной процедурой
  при обновлении программы через PowerShell.

## Не использовать устаревший набор 2017 года

Открытый набор Минздрава 7707778246-grls, видимый по адресу
https://minzdrav.gov.ru/opendata/7707778246-grls,
в последний раз обновлялся 01.03.2017. Этот набор не подходит для
определения актуального статуса регистрации по состоянию на 2026 год.

## Следующий самостоятельный этап

После выяснения доступных условий автоматизированного подключения
официальных источников можно добавить периодическое скачивание
новых снимков, сверку изменений по регистрационному номеру,
отдельные сведения об истории регистрации и независимую проверку
всех сопоставлений. Автоматическая клиническая интерпретация
данных в этот план не входит.
