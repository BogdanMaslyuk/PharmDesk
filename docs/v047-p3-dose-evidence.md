# PharmDesk 0.4.7 P3 — дозировки и тип высвобождения

## Отправная точка

Исторический локальный анализ алгоритма `0.4.7-evidence-1` оценил 36 865 кандидатов
для 1 131 товарной позиции. 14 первых кандидатов имели критические расхождения,
ещё 2 позиции потеряли прежние сопоставления. Конкретные товарные строки изучались
**локально** и не копировались в репозиторий.

Отдельный тестовый код изолирован от рабочей SQLite. Ветка `main` не менялась.

## Научно-техническая причина исправлений

1. В товарных записях распространены дозировки в мкг; источник может представлять
   ту же массу в мг. Перевод `1000 мкг = 1 мг` выполняется точно через `Decimal`,
   включая мкг/мл → мг/мл. Это преобразование единиц, а не установление состава.
2. Процентные концентрации могут сопоставляться с мг/мл только при доказанном
   основании концентрации и лекарственной форме. Возможная числовая эквивалентность
   (5% и 50 мг/мл; 0,75% и 7,5 мг/мл) помечается `ambiguous`, **не** `match`.
3. Испорченный десятичный разделитель (например, `69, 19 мг/мл`) разбирается
   с флагом неопределённости. Оборванное `7,5мг/` не становится точной дозировкой.
4. `модиф.`, `МВ` и `пролонг.` признаются свидетельствами модифицированного
   высвобождения. Отсутствие указания в источнике — `unknown`, а не доказанный
   `conflict` или обычное высвобождение.
5. Для «сильного» кандидата недостаточно отсутствия конфликта, если у товара
   явно заявлено модифицированное высвобождение, а у источника этот признак неизвестен.
6. Существуют препараты с числовым окончанием полного торгового названия
   (например, «Фемостон 1» и «Фемостон 2»). Нельзя подменять их общим названием.
   Если в конкретном загруженном снимке отсутствует точное название, позиция
   остаётся без кандидата и отправляется на ручную сверку.

## Как проверить на уже существующей тестовой базе Windows

Исходный тестовый код находится по пути:

`Desktop\PharmDesk_Project\_Validation_047\PharmDesk-v047`

Остановить основной сервер. Действовать **только в этом отдельном тестовом clone**.

```powershell
cd "$env:USERPROFILE\Desktop\PharmDesk_Project\_Validation_047\PharmDesk-v047"
git fetch origin feature/v047-p3-dose-evidence-audit
if ($LASTEXITCODE -ne 0) { throw "Ошибка загрузки ветки" }
git switch -c feature/v047-p3-dose-evidence-audit --track origin/feature/v047-p3-dose-evidence-audit
if ($LASTEXITCODE -ne 0) { throw "Ошибка переключения тестовой ветки" }

.\.venv\Scripts\python.exe -X utf8 -m pytest -q
if ($LASTEXITCODE -ne 0) { throw "Автотесты не прошли; анализ не запускать" }

.\.venv\Scripts\python.exe -X utf8 -m scripts.v047_p3_compare
if ($LASTEXITCODE -ne 0) { throw "P3 завершился с ошибкой" }
Get-Content "..\reports\p3_comparison_v1_v2.json" -Raw -Encoding UTF8
```

**Не выполнять** `validate-v047-windows.ps1 -Action Prepare` или
`-Action Run` повторно: это прежний воспроизводимый сценарий алгоритма v1.
Новый P3 запускается исключительно через `scripts.v047_p3_compare`.

## Что делает P3

- Проверяет существующую неизменяемую базовую копию и путь тестовой SQLite.
- Сохраняет отпечатки всех ранее записанных строк исторических таблиц.
- Создаёт **новый запуск алгоритма** `0.4.7-evidence-2` (не удаляя №1/№2).
- Повторно оценивает весь ассортимент на том же снимке ГРЛС.
- Сравнивает алгоритмы v1 → v2 и выгружает локальные результаты.
- После выполнения проверяет контрольные суммы защищённых исходных таблиц и
  исторических строк, существовавших до запуска.
- Отказывается повторно создавать запуск v2 или перезаписывать отчёты.

Локальные результаты:

- `reports/p3_comparison_v1_v2.json` — агрегаты, можно прислать в чат.
- `reports/p3_candidate_deltas_v1_v2.csv` — содержит внутренние товарные
  коды и названия; сохранять локально, не отправлять в публичный GitHub.

## Чего пока не доказали

Нет проверки полной идентичности препаратов, актуального статуса регистрационных
удостоверений, состава упаковок или медицинской взаимозаменяемости.
Исходные длинные поля ГРЛС могут содержать несколько разных форм и дозировок;
их связь с конкретным выпуском ещё требует ручного подтверждения.

Нельзя объявлять исправленными все 14 конфликтов на основании синтетических тестов:
сначала сравнить результаты P3 и перепроверить точные исходные строки ГРЛС.

**Статус:** экспериментальная ветка. Внедрение запрещено до проверки результатов.
