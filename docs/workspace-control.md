# PharmDesk v0.4.6 — единое рабочее пространство и пульт Windows

## Назначение

На рабочем столе могут остаться три папки:

- `PharmDesk-git` — **основной рабочий репозиторий** с актуальной SQLite;
- `PharmDesk-main` — предыдущая копия из скачанного архива;
- `PharmDesk-git-before-fix` — старая рабочая копия.

**Никакие папки не следует удалять или объединять вручную.**
Скрипт `organize-desktop.ps1` предлагает создать общую папку
`%USERPROFILE%\Desktop\PharmDesk_Project`.

После переноса структура:

```text
Рабочий стол/
└── PharmDesk_Project/
    ├── PharmDesk-Control.bat       ← главный ярлык-пульт
    ├── README-Workspace.txt
    ├── PharmDesk-git/              ← ЕДИНСТВЕННЫЙ рабочий проект
    │   ├── app/
    │   ├── .git/
    │   ├── .venv/
    │   ├── pharmdesk.sqlite3       ← действующая база
    │   ├── private_data/           ← изображения, если имеются
    │   ├── backups/                ← проверенные резервные копии
    │   ├── .run/                   ← локальные журналы и PID; игнорируется Git
    │   ├── control-windows.bat
    │   └── control-windows.ps1
    └── _Old_versions/             ← хранение предыдущих папок без удаления
        ├── PharmDesk-main/
        └── PharmDesk-git-before-fix/
```

Содержимое старых папок сохраняется целиком. До отдельного подтверждения
сохранности основной базы ничего из них не удалять.

## Перед переносом

1. Убедитесь, что все окна работающего PharmDesk закрыты:
   пульт — действие «Остановить сервер»; обычный PowerShell —
   `Ctrl+C`. Закройте также программы, открывшие файлы в старых папках.
2. Откройте **новое окно PowerShell**, находясь в домашней папке,
   а не внутри `PharmDesk-git`.
3. Обновите действующий репозиторий:
   ```powershell
   cd "$env:USERPROFILE\Desktop\PharmDesk-git"
   .\update-windows.bat
   ```
4. Вернитесь в домашнюю папку и выполните **предварительный просмотр**:
   ```powershell
   cd $env:USERPROFILE
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\PharmDesk-git\organize-desktop.ps1"
   ```
5. Проверьте, что действующий каталог — `PharmDesk-git` и именно
   в нём имеется база. Выполните сам перенос:
   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Desktop\PharmDesk-git\organize-desktop.ps1" -Apply
   ```
   Подтвердите словом `ПЕРЕНЕСТИ`.
6. Откройте `PharmDesk_Project\PharmDesk-Control.bat`.
   Нажмите 3, чтобы проверить SQLite и количество товаров/строк ГРЛС.

**Скрипт работает по правилу «сначала показать, потом изменить»:**
до `-Apply` только читает информацию о папках. В режиме применения
он проверяет занятость порта 8000, наличие репозитория и кода,
не допускает конфликтующих путей, делает согласованную резервную
копию SQLite с фотографиями, перемещает каталоги целиком и создаёт
пульт верхнего уровня. **Нет** удаления, `git reset --hard`,
объединения, перезаписи содержимого и автоматической очистки.

При ошибке перенос прекращается, уже перемещённые папки остаются
на месте и могут быть безопасно проверены; скрипт можно повторить,
если конфликтов нет. В случае более свежих данных в старых папках
их нужно сравнить отдельно до удаления архива.

## Пульт управления

В `PharmDesk_Project` запускайте **только**
`PharmDesk-Control.bat` двойным нажатием. Старое имя
`pharmdesk.bat` внутри кода осталось совместимым и открывает
тот же пульт.

| Команда | Действие |
|---|---|
| 1 | Запустить локальный сервер и открыть сайт |
| 2 | Открыть сайт в браузере без повторного запуска |
| 3 | Состояние сервера, версия Git, диагностика SQLite, товары, ГРЛС, изображения |
| 4 | Создать согласованную резервную копию базы и фотографий |
| 5 | Обновить код через безопасный `git pull --ff-only` |
| 6 | Запустить автоматические тесты |
| 7 | Открыть страницу массовой проверки ГРЛС |
| 8 | Открыть журнал сервера и рабочую папку |
| 9 | Остановить **только** сервер, который был запущен этим пультом |
| 0 | Закрыть пульт, не останавливая работающий сервер |

Один локальный сервер FastAPI обслуживает **и сайт (HTML/JavaScript),
и API** на адресе `http://127.0.0.1:8000`. Отдельного
сервера фронтенда в PharmDesk нет.

Процесс запускается в фоновом режиме и пишет журналы в `.run/`,
которая не добавляется в Git. Пульт хранит идентификатор процесса и
перед остановкой проверяет исполняемый путь и параметры запуска.
**Чужой процесс на порту 8000 не завершается**; если сайт был запущен
через прежнюю команду, останавливайте его `Ctrl+C` в прежнем окне.

При обновлении сервер должен быть остановлен. Если локальный код
изменён, обновление не выполняет принудительный сброс.

## Восстановление после переноса

- Основная SQLite остаётся **внутри перемещённой рабочей папки**;
  перенос не создаёт новую пустую базу.
- Проверка: пульт → 3. Сверьте товарные позиции, ящики, строки ГРЛС.
- Дополнительная копия: пульт → 4. Архивы не зашифрованы.
- Если диагностика обнаружила другую базу, остановите использование
  программы и выясните путь: переменная `DATABASE_URL` может
  перенаправлять SQLite.
- Не копируйте `pharmdesk.sqlite3` поверх активной базы вручную.
- Старые папки из `_Old_versions` не удаляйте до проверки
  диагностического отчёта и наличия резервных копий.

## Команды без меню

```powershell
cd "$env:USERPROFILE\Desktop\PharmDesk_Project\PharmDesk-git"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\control-windows.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\control-windows.ps1 -Action Diagnose
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\control-windows.ps1 -Action Backup
```

## Ограничения

- Автоматически манипулировать файлами компьютера пользователя
  из GitHub нельзя: `-Apply` пользователь запускает **локально**.
- Пульт рассчитан на один локальный экземпляр на порту 8000.
- Если Windows блокирует перемещение открытого каталога, закрыть
  процессы, которые удерживают файлы, и повторить перенос.
- Не импортировать данные из старых папок вслепую:
  содержащиеся там SQLite могут представлять отдельные состояния
  ассортимента.
