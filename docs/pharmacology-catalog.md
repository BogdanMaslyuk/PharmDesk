# PharmDesk v0.4.0 — справочник зарегистрированных лекарственных препаратов

## Что это за версия

PharmDesk хранит локальный ассортимент аптеки **отдельно** от
сведений о зарегистрированных препаратах, записанных человеком
по официальному источнику. Версия 0.4 **не подключает автоматически**
Государственный реестр лекарственных средств (ГРЛС), не скачивает
инструкции и не пытается определять действующее вещество по названию
товара. Это управляемая основа справочника с прослеживаемыми источниками.

Официальные источники для ручной сверки:

- Государственный реестр лекарственных средств Минздрава России:
  https://grls.rosminzdrav.ru/
- Единый реестр зарегистрированных лекарственных средств ЕАЭС:
  https://pharma.eaeunion.org/pharma/registers/26/ru/

Министерство здравоохранения РФ подтверждает адрес первого реестра:
https://minzdrav.gov.ru/opendata/7707778246-grls

**Важно:** в PharmDesk требуется ссылка на конкретную реестровую
запись либо инструкцию. Ссылка на главную страницу не позволяет
подтвердить конкретные данные.

## Как вносить препарат

1. Откройте «Препараты», затем товарную карточку, например
   товар с кодом из выбранного ящика.
2. Перейдите в «Связь с Государственным реестром».
3. Откройте официальный источник отдельно, найдите **точный номер
   регистрационного удостоверения** и запись подходящей формы/дозировки.
4. Перепишите регистрационный номер, торговое название, лекарственную
   форму, дозировку, производителя (если указан), а также действующие
   вещества (каждое на отдельной строке).
5. Вставьте адрес конкретной реестровой записи или инструкции.
6. Лично проверьте, что запись соответствует товару. Подтвердите обе
   галочки и сохраните запись.
7. Если название или дозировка не похожи на товарную строку,
   обязательно объясните причину в примечании. Нельзя автоматически
   считать такое совпадение правильным.
8. В разделе «Справочник» будут отображаться введённые записи,
   состав и ссылки на источники, явно помеченные как **«Внесено вручную»**.

Если нужная регистрационная карточка уже существует в локальном справочнике,
используйте «Связать с уже внесённой карточкой», а не создавайте копию.

## Техническое разделение данных

- **Medicine** — товарное наименование из внутренней базы аптеки
  (не номер регистрационного удостоверения).
- **StockItem** — конкретный код товара и ящик; факт записи не означает
  реальный остаток или наличие.
- **RegisteredProduct** — ручная запись с регистрационным номером,
  торговым названием, формой, дозировкой, производителем, источником
  и датой проверки.
- **RegisteredSubstance / RegisteredComposition** — названия действующих
  веществ, переписанные из указанного источника для этой записи.
- **MedicineRegistrationLink** — явно подтверждённая пользователем
  связь конкретной товарной карточки с зарегистрированным препаратом.
- **RegistryLinkEvent** — история ручных решений с комментариями,
  включая отмену и повторное связывание.

Новые сущности созданы **в отдельных таблицах**.
Существующие таблицы, коды товаров и содержимое ящиков не меняются
при установке версии 0.4.

## Исправление ошибочного сопоставления

Откройте связанную товарную карточку и раздел сопоставления.
Для неправильной связи выберите «Отменить связь», запишите причину
и явно подтвердите словом ОТМЕНИТЬ.

Одна товарная карточка может иметь только одну активную связь с регистрационной карточкой. Для исправления ошибочного соответствия сначала отмените старую связь, затем подтвердите новую.

Запись зарегистрированного препарата и товарная строка остаются в базе.
История отмены сохраняется, даже если впоследствии связь будет
восстановлена после новой ручной проверки.

## Что справочник НЕ умеет и не утверждает

- Не проверяет через сеть актуальный статус регистрации
  (действует, отменено, приостановлено).
- Не удостоверяет, что пользователь безошибочно переписал инструкцию.
- Не извлекает данные автоматически из сайтов реестров.
- Не определяет взаимозаменяемость на основании одинакового МНН.
- Не даёт рекомендации по лечению и не проверяет взаимодействия.
- Не переносит состав в старую таблицу Ingredient и не использует
  зарегистрированные вещества для автоматических клинических выводов.
- Не подменяет инструкцию, фармацевтическую консультацию или назначение врача.

## Обновление и защита данных

Сначала остановите сервер PharmDesk (Ctrl+C в его окне), затем выполните
в папке `PharmDesk-git`:

    .\update-windows.bat

Обновляющий скрипт создаёт резервную копию SQLite и локальных снимков
перед получением изменений GitHub. Запуск `pharmdesk.bat` даёт меню
резервного копирования и диагностики. Новые таблицы создаются
приложением без удаления старых записей.

Реальные аптечные файлы, SQLite и фотографии **не загружаются** в
публичный GitHub. Для перехода на другую машину переносите вместе
резервную копию базы и фотографии.

## Следующий самостоятельный этап

Для получения автоматического наполнения справочника потребуется
отдельное техническое задание: проверить доступные официальные
форматы выгрузки, правовые условия повторного использования и
актуальность данных; создать загрузчик с версионированием;
проверить регистрацию по идентификатору, а не по одному названию;
добавить процедуру независимого контроля и обновления статусов.
Без этих этапов нельзя выдавать автоматические результаты за
достоверную фармакологическую информацию.
