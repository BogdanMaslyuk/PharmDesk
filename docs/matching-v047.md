# PharmDesk 0.4.7-rc1 — сопоставление с ГРЛС: качество и аудит

**Статус:** кандидат на выпуск; не медицинская валидация. Разработка на отдельной ветке.

## Что исправлено

- Для каждого товарного названия ищутся все точные регистрационные строки, затем извлечённые признаки сравниваются **до** ограничения выдачи 30 кандидатами.
- Кандидаты сортируются по отсутствию критических противоречий, совпадению названия, формы и дозировки, затем по неопределённости и вспомогательным данным. При равенстве — стабильный идентификатор регистрационной записи. Статус из файла ГРЛС не считается подтверждением регистрации.
- Для защиты от аномально больших выборок действует верхний предел вычислений 2000 строк на товар. Если он достигнут, интерфейс прямо сообщает, что выбор неполный.
- Торговое название разрешается только по **полным названиям из выбранного снимка**. Числа, входящие в название, и маркетинговые суффиксы не отбрасываются только потому, что у семейства есть короткое имя.
- Диагностика каждого запуска: `/manage/matching/{id}/audit` и `/manage/matching/{id}/audit.json`, включая счётчики видимых кандидатов, скрытых альтернатив и исходов проверки каждого сохранённого признака.
- Для старых запусков (0.4.5) отчёт честно указывает, что число полностью проанализированных строк неизвестно: нельзя восстановить его задним числом.

## Что намеренно не изменено

- Исходная SQLite, товары, ящики, ГРЛС, ручные связи и история сопоставлений не редактируются этим обновлением.
- Категория «сильный кандидат» по-прежнему не равнозначна ручному подтверждению. При нескольких строках с одним торговым названием итоговая категория остаётся неоднозначной, даже если лучший кандидат совпал по извлечённым признакам.
- Многовариантные формы выпуска и неполные комбинированные дозы остаются неопределёнными. Нельзя конструировать искусственные сочетания из разных фрагментов записи.
- Нет проверки текущего статуса регистрации, состава конкретной упаковки, терапевтической взаимозаменяемости или взаимодействий лекарств.

## Проверка и установка

Запустить проверку GitHub Actions, затем независимо проверить на локальном компьютере (в отдельной тестовой копии базы) новый запуск с алгоритмом `0.4.7-evidence-1`. Он **не должен заменять** результаты проверки №1. Сравнить диагностические агрегаты, особенно группы с более чем 30 кандидатами.

До обновления действующего каталога: остановить сервер, создать резервную копию, провести автоматические тесты и ручную проверку минимум 200 реальных товарных позиций по исходным регистрационным документам.

**Не выгружать** `pharmdesk.sqlite3`, резервные копии или оригинальный экспорт аптечного ассортимента в публичный GitHub.

## Ограничения этой первой реализации

Группировка дублей по регистрационным номерам в визуальном представлении и разбор связанных пар «форма–доза» в длинном поле ГРЛС остаются отдельными задачами. Диагностика признаков описывает сохранённые отображённые кандидаты; признаки для скрытых строк используются при ранжировании, но не сохраняются в полной доказательной таблице.
