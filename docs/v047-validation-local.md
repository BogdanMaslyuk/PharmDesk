# PharmDesk v0.4.7 — локальный запуск проверки P1/P2 на Windows

**Статус:** предварительные испытания. НЕ обновлять основную программу `PharmDesk-git`; НЕ сливать PR №14 и №15 до локальной и ручной проверки.

## Что уже проверено в GitHub

- Единая функция безопасного извлечения полного торгового названия для массовой проверки и карточек.
- Синтетические регрессионные тесты.
- Полный сценарий с изолированной синтетической SQLite: `prepare → run → integrity + comparison`.
- Все приватные данные остаются на компьютере; репозиторий содержит только код и учебные примеры.

## Перед запуском

1. Закрыть сайт PharmDesk из основного пульта (пункт 9), а если он был запущен отдельно — остановить соответствующий PowerShell через Ctrl+C.
2. Открыть новое окно Windows PowerShell.
3. Убедиться, что свободно не менее 1,2–1,5 ГБ диска (в зависимости от фактического размера SQLite; сценарий проверяет запас).
4. Не удалять и не переносить `PharmDesk_Project/PharmDesk-git`, `backups` или `_Old_versions`.

## Шаг 1 — новая независимая копия кода

```powershell
cd "$env:USERPROFILE\Desktop\PharmDesk_Project"
New-Item -ItemType Directory -Force -Path "_Validation_047" | Out-Null
git clone --branch feature/v047-validation-safety --single-branch https://github.com/BogdanMaslyuk/PharmDesk.git "_Validation_047\PharmDesk-v047"
cd "_Validation_047\PharmDesk-v047"
```

Нельзя выполнять этот этап в уже существующей рабочей папке `PharmDesk-git`. Если папка `_Validation_047\PharmDesk-v047` уже существует, команда clone должна остановиться; **не удалять её вслепую**.

## Шаг 2 — подготовка и проверка копии базы

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\validate-v047-windows.ps1 -Action Prepare
```

Сценарий создаёт отдельное виртуальное окружение и запускает весь набор автоматических тестов. Если они прошли, он проверяет, что порт 8000 не занят, создаёт согласованную резервную копию SQLite и вторую тестовую копию.

Сохраняются:
- `_Validation_047/backups/baseline_*.sqlite3` — неперезаписываемая копия;
- `_Validation_047/database/pharmdesk_validation.sqlite3` — тестовая база;
- `_Validation_047/reports/baseline_manifest.json` — контрольные суммы, снимок структуры и содержимого основных таблиц, история прошлых запусков.

**Не продолжать**, если проверка сообщает о нарушенных внешних ключах, повреждении SQLite, недостаточном месте или ошибке путей. Скрипт отказывает при запуске из рабочего каталога.

## Шаг 3 — выполнить алгоритм на тестовой базе

Только после успешного шага 2:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\validate-v047-windows.ps1 -Action Run
```

Этот шаг **не запускает основной сайт**. Используется отдельная тестовая SQLite, URL проверяется перед импортом модулей приложения. Добавляется новый запуск сопоставления; исходный ассортимент, данные ГРЛС и исторические строки перепроверяются по контрольным отпечаткам.

Локальные результаты:
- `_Validation_047/reports/matching_diagnostic.json` — статистика новой проверки;
- `_Validation_047/reports/comparison_v045_v047.csv` — сравнение товаров (приватный файл);
- `_Validation_047/reports/integrity_report.json` — контроль сохранности.

## Что прислать для продолжения

Сначала — только текст вывода команды `Prepare`. После `Run` — текст её вывода и `matching_diagnostic.json`. Выгрузка `comparison_v045_v047.csv` содержит внутренние сведения аптеки и **не должна загружаться в публичный GitHub**.

## Ограничения

- Используется снимок ГРЛС из локальной базы. Реальные результаты на 22.11.2026 ещё не проверены.
- Тестовый CSV пригоден для дальнейшего анализа; отдельный итоговый оформленный Excel-отчёт и стратифицированная выборка для независимой проверки формируются на последующих этапах.
- Отсутствие ошибок в тестах не доказывает идентичности лекарственных препаратов, действительность регистрационных удостоверений или взаимозаменяемость.
- Не проверены реальные упаковки и регистрационные документы. До их проверки нельзя принимать решение GO.
- Скрипт резервирует SQLite. Если в рабочем `private_data` появятся изображения или другие вложения, их необходимо отдельно учитывать в плане полного восстановления.

## Шаг 4 — локальная очередь первичной ручной проверки (после Run)

Обновить только отдельный тестовый код. Не запускать `Prepare` или `Run` повторно.

```powershell
cd "$env:USERPROFILE\Desktop\PharmDesk_Project\_Validation_047\PharmDesk-v047"
git pull --ff-only origin feature/v047-validation-safety
.\.venv\Scripts\python.exe -X utf8 -m scripts.v047_review_triage
```

Команда открывает тестовую SQLite **только для чтения**, проверяет исходные защищённые таблицы и старую историю и создаёт два файла в `_Validation_047\reports`:

- `quality_triage_v047.json` — агрегаты, исходы формы и дозировки для первых кандидатов, группы изменений и категории новой проверки. Не содержит названий или артикулов товаров.
- `manual_review_priority_50.csv` — 50 уникальных товаров для целевой первичной ручной проверки, с кодами, названиями, старым и новым регистрационными кандидатами и пустыми полями ручного решения. Это **локальный приватный файл**.

**Не считать эту выборку случайной или репрезентативной.** Для расчёта показателей точности позже нужен отдельно зафиксированный случайный/стратифицированный отбор с ручным эталоном.

Прислать только текст успешного вывода команды и содержимое `quality_triage_v047.json`. Приватный CSV не загружать в GitHub.
