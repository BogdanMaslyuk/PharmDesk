# Эксплуатация PharmDesk v0.3.1 в Windows

## Единое меню

В папке проекта запустите pharmdesk.bat двойным щелчком или через PowerShell:

    cd "$env:USERPROFILE\Desktop\PharmDesk-git"
    .\pharmdesk.bat

Меню: 1 — запуск; 2 — обновление; 3 — резервная копия; 4 — диагностика;
5 — тесты; 0 — выход. Файл pharmdesk.ps1 можно запустить через
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\pharmdesk.ps1,
если Windows блокирует непосредственный запуск PS1.
Не требуется глобально изменять политику исполнения скриптов.

## Безопасное обновление

1. Остановите PharmDesk (Ctrl+C в окне сервера).
2. Запустите меню и выберите 2.
3. Скрипт проверяет репозиторий BogdanMaslyuk/PharmDesk, ветку main,
   отсутствие локальных изменений кода и свободный порт 8000.
4. Если есть локальная SQLite-база, создаётся согласованная копия
   средствами SQLite вместе с фотографиями. При сбое копирования
   получение обновления отменяется.
5. Используется git pull --ff-only origin main, установка зависимостей
   и все тесты. Нет git reset --hard и удаления пользовательских файлов.

ВАЖНО: при первом переходе с v0.3.0 обновление выполняет ещё прежний
скрипт, пока новый не будет получен из GitHub. Поэтому перед первым
обновлением обязательно остановите сервер; при желании сохраните
дополнительную копию закрытого файла SQLite в защищённом месте.

## Резервная копия

Пункт 3 запускает модуль app.maintenance backup.
Архив backups/pharmdesk_YYYYMMDD_HHMMSS_xxxxxx.zip содержит:
- database/pharmdesk.sqlite3 — согласованный снимок SQLite, включая WAL;
- review_images/ — локальные оригиналы снимков;
- manifest.json — время, версия, контрольные суммы SHA-256.

Архив проверяется перед публикацией в папке backups.
Архив НЕ зашифрован — нельзя выкладывать в публичный GitHub или
общие папки без защиты. Никогда не помещайте реальные аптечные данные
в открытые репозитории.

## Диагностика

Пункт 4 выполняет app.maintenance diagnose:
- PRAGMA integrity_check в SQLite, чтение только;
- проверка необходимых таблиц;
- подсчёт ящиков, товарных позиций, очереди сверки и статусов;
- поиск недостающих файлов оригинальных фотографий.

Не создаёт пустую базу, не меняет схему, не удаляет и не исправляет записи.
Отсутствие части фото — отдельное предупреждение.

## Восстановление

Автоматического восстановления в этой версии НЕТ: оно может затереть
более поздние исправления. Для восстановления остановите сервер,
сохраните отдельную копию текущих данных, проверьте архив и восстановите
SQLite и оригинальные фото согласованно после явного решения.

## Проверка ассортимента

В /review раскрывается таблица прогресса по ящикам (все, подтверждено,
ожидают, исключено и процент завершения).
На странице товара снимок увеличивается кнопками до 400% с прокруткой.
Ручное подтверждение требует исходной фотографии.
CSV-импорт сообщает число строк, защищённых от перезаписи старым OCR.
Ручное изменение ранее подтверждённого товара снова требует проверки,
но сохраняет блокировку старых и исправленных кодов при новом импорте.

## Ограничения

Нет автоматического получения данных ГРЛС, определения аналога или
лекарственных взаимодействий. В этой версии программа остаётся
локальным средством учёта и проверки названий товаров.
