# PharmDesk — рабочее место фармацевта

**PharmDesk v0.2.0** — локальное веб-приложение для навигации по аптечным ящикам, поиска товаров и формирования основы лекарственного справочника.

Это ранний технический прототип. Он не является системой назначения лечения и **не проводит проверку лекарственных взаимодействий**.

## Что работает

- Карта ящиков с названиями категорий хранения и поиском.
- Создание и редактирование ящиков, добавление, исправление, перенос и удаление товарных позиций через сайт.
- Просмотр товарных позиций в выбранном ящике.
- Поиск препаратов по наименованию, коду, производителю или сопоставленному действующему веществу с учётом регистра, «е/ё», нескольких слов и выбором ящика.
- Быстрые подсказки при вводе названия.
- Товарные карточки с местами хранения.
- Импорт CSV и XLSX: несколько ящиков в одном файле, проверка перед сохранением, выявление ошибок, повторное обновление позиций по коду внутри ящика.
- Локальный журнал действий при редактировании и импорте.
- Модели для действующих веществ, клинических записей с проверенным источником и взаимодействий.
- Локальный интерфейс и API; автоматические тесты.
- **Только вымышленные учебные данные** в примере №101.

**Важно:** запись в ассортименте не подтверждает реальный остаток. Из выгрузки, содержащей только наименование, производителя и код, нельзя автоматически достоверно установить действующее вещество, показания, противопоказания, совместимость и зарегистрированные дозировки. Соответствующие поля не заполняются неподтверждёнными сведениями.

## Запуск на Windows

Понадобится Python 3.11 или новее. Скачайте репозиторий через **Code → Download ZIP** и распакуйте папку.

1. Запустите `setup-windows.bat`: установятся зависимости, появится локальная база с вымышленным ящиком №101.
2. Запустите `start-windows.bat`.
3. Откройте **http://127.0.0.1:8000** в браузере.

Те же действия через PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.cli seed-demo
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m app.cli seed-demo
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть API: **http://127.0.0.1:8000/docs**.

Для пустой базы пропустите команду `seed-demo`.

## Сохранение данных при обновлении с v0.1

При обновлении приложения **не удаляйте свою базу данных**. Сначала закройте окно запуска программы. Найдите в старой папке файл `pharmdesk.sqlite3`, сделайте его резервную копию и перенесите этот файл в новую папку проекта (заменив пустую учебную базу, если она появилась). Других файлов данных переносить не требуется. В v0.2 новая таблица журнала будет создана автоматически.

Если в предыдущей версии был только вымышленный ящик №101 и собственные данные не вносились, можно просто распаковать новую версию и запустить `setup-windows.bat`.

**Для повседневной работы:** откройте `/manage` — раздел «Управление». Создавайте ящики, добавляйте записи и переходите к `/manage/import` для массового импорта. При загрузке файла сначала нажмите «Проверить файл», затем — «Подтвердить импорт».

## Импорт своего ящика

Экспорт в CSV с разделителем `;` (в кодировке UTF-8) или в XLSX. Необходимые колонки:

| Ящик | Название ящика | Код | Наименование товара | Производитель | Дата добавления |
| --- | --- | --- | --- | --- | --- |
| 23 | Учебный ящик | DEMO-01 | Парацетамол учебный таб. 500мг №10 | Учебный производитель | 01.01.2026 |

Если все позиции относятся к одному ящику, столбец «Ящик» можно опустить и указать номер в форме импорта. Столбцы «Код» и «Наименование товара» обязательны.

Альтернативно для импорта одного ящика из командной строки:

```sh
python -m app.cli import-stock "C:/data/your-export.xlsx" --drawer 23 --drawer-name "Название ящика"
```

Повторный импорт обновляет позиции с прежним кодом в том же ящике. **Не удаляет** позиции, отсутствующие в следующей выгрузке: экспорт может быть неполным. Программа не делает медицинских выводов и не угадывает остатки.

Если загружается несколько ящиков, выполните команду для каждого. Данные сохраняются в локальной SQLite-базе `pharmdesk.sqlite3` (игнорируется Git).

## Важные ограничения

- Первый запуск — **локально на компьютере**, без авторизации и без доступа извне. Запускать только с адресом `127.0.0.1`. На других компьютерах не открывать сервис без отдельного внедрения защиты.
- Данные аптеки хранятся в `pharmdesk.sqlite3`, который не должен попадать в GitHub. Для резервного копирования закройте приложение и скопируйте файл в защищённое место.
- В режиме предпросмотра изменения не сохраняются. При подтверждении новые и изменённые строки обрабатываются одной транзакцией; ошибочные строки перечисляются в отчёте и пропускаются.
- Импорт **никогда не удаляет** позиции, отсутствующие в очередной выгрузке. В каждом ящике один и тот же код не может использоваться дважды, но товар может храниться в нескольких ящиках.
- Сайт не умеет определять наличие по остаткам, не содержит проверенную базу лекарственных взаимодействий и не должен использоваться для медицинских решений.

## Структура проекта

```text
app/
  main.py           HTML-страницы и API
  models.py         Ящики, товары, вещества, клинические сведения
  database.py       Локальная БД SQLite
  importer.py       Загрузка отдельного ящика
  batch.py          Предпросмотр и импорт нескольких ящиков

  static/           Стили и JavaScript
examples/           Только вымышленные примеры
tests/              Автоматические тесты
.github/workflows/  Проверка в GitHub Actions
```

## Приоритеты следующего этапа

1. Подтверждённое разделение товара, дозировки, формы и размера упаковки; дальнейшее улучшение поиска и синхронизации остатков.
2. Подтверждённое сопоставление торговых наименований с международными непатентованными наименованиями (МНН) и официальными инструкциями, ссылка и дата сверки.
3. Аналоги по одному действующему веществу отдельно от терапевтических альтернатив, без автоматических рекомендаций о замене терапии.
4. Проверенная лицензированная база взаимодействий и клиническое тестирование — только после этого допускается вывод предупреждений.
5. Пользовательские роли, аудит изменений, резервное копирование, миграции данных, безопасное развёртывание.

## Конфиденциальность и пределы применения

- По умолчанию сервер слушает **только 127.0.0.1** и **не имеет авторизации**. **Не публикуйте его в интернете или локальной сети** без защиты.
- Не загружайте данные пациентов: ФИО, рецепты, сведения о заболеваниях, контакты. Тестовый список лекарств не сохраняется в базе.
- В публичный репозиторий нельзя добавлять служебные аптечные выгрузки, коды, остатки или иные конфиденциальные сведения без законного основания и разрешения.
- **Отсутствие обнаруженных взаимодействий не доказывает безопасность.** Сейчас `/api/interactions/check` всегда сообщает, что проверка не выполнена.
- Для реальной работы предпочтителен **закрытый репозиторий**; сам репозиторий не следует использовать для хранения персональных данных.
