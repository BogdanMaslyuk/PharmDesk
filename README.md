# PharmDesk — рабочее место фармацевта

**PharmDesk v0.1.0** — локальное веб-приложение для навигации по аптечным ящикам, поиска товаров и формирования основы лекарственного справочника.

Это ранний технический прототип. Он не является системой назначения лечения и **не проводит проверку лекарственных взаимодействий**.

## Что работает

- Карта ящиков с названиями категорий хранения и поиском.
- Просмотр товарных позиций в выбранном ящике.
- Поиск препаратов по наименованию, коду, производителю или сопоставленному действующему веществу.
- Товарные карточки с местами хранения.
- Импорт CSV и XLSX, повторное обновление позиций по коду внутри ящика.
- Модели для действующих веществ, клинических записей с проверенным источником и взаимодействий.
- Локальный интерфейс и API; автоматические тесты.
- **Только вымышленные учебные данные** в примере №101.

**Важно:** запись в ассортименте не подтверждает реальный остаток. Из выгрузки, содержащей только наименование, производителя и код, нельзя автоматически достоверно установить действующее вещество, показания, противопоказания, совместимость и зарегистрированные дозировки. Соответствующие поля не заполняются неподтверждёнными сведениями.

## Запуск на Windows

Понадобится Python 3.11 или новее. Скачайте репозиторий через **Code → Download ZIP** и распакуйте папку.

1. Запустите `setup-windows.bat`: установятся зависимости, появится локальная база с вымышленным ящиком №101.
2. Запустите `start-windows.bat`.
3. Откройте **http://127.0.0.1:8000** в браузере.

Те же действия через PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.cli seed-demo
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m app.cli seed-demo
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открыть API: **http://127.0.0.1:8000/docs**.

Для пустой базы пропустите команду `seed-demo`.

## Импорт своего ящика

Экспорт в CSV с разделителем `;` или в XLSX. Необходимые колонки:

| Код | Наименование товара | Производитель | Дата добавления |
| --- | --- | --- | --- |
| DEMO-01 | Парацетамол учебный таб. 500мг №10 | Учебный производитель | 01.01.2026 |

Из каталога проекта:

```sh
python -m app.cli import-stock "C:/data/your-export.xlsx" --drawer 23 --drawer-name "Название ящика"
```

Повторный импорт обновляет позиции с прежним кодом в том же ящике. **Не удаляет** позиции, отсутствующие в следующей выгрузке: экспорт может быть неполным. Программа не делает медицинских выводов и не угадывает остатки.

Если загружается несколько ящиков, выполните команду для каждого. Данные сохраняются в локальной SQLite-базе `pharmdesk.sqlite3` (игнорируется Git).

## Приоритеты следующего этапа

1. Несколько ящиков: единый импорт, структурированная информация о дозировке, форме и количестве в упаковке.
2. Подтверждённое сопоставление торговых наименований с международными непатентованными наименованиями (МНН) и официальными инструкциями, ссылка и дата сверки.
3. Аналоги по одному действующему веществу отдельно от терапевтических альтернатив, без автоматических рекомендаций о замене терапии.
4. Проверенная лицензированная база взаимодействий и клиническое тестирование — только после этого допускается вывод предупреждений.
5. Пользовательские роли, аудит изменений, резервное копирование, миграции данных, безопасное развёртывание.

## Конфиденциальность и пределы применения

- По умолчанию сервер слушает **только 127.0.0.1** и **не имеет авторизации**. **Не публикуйте его в интернете или локальной сети** без защиты.
- Не загружайте данные пациентов: ФИО, рецепты, сведения о заболеваниях, контакты. Тестовый список лекарств не сохраняется в базе.
- В публичный репозиторий нельзя добавлять служебные аптечные выгрузки, коды, остатки или иные конфиденциальные сведения без законного основания и разрешения.
- **Отсутствие обнаруженных взаимодействий не доказывает безопасность.** Сейчас `/api/interactions/check` всегда сообщает, что проверка не выполнена.
- Для реальной работы предпочтителен **закрытый репозиторий**; сам репозиторий не следует использовать для хранения персональных данных.
